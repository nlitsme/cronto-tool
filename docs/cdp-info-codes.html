DIGIPASS · Secure Channel · C0 command family

CDP Info query codes

The C0 device-info codes ask a Cronto hardware token to display one of its own attributes — the reader labels this family “CDP info”. Each code below is one query: it carries only a 1-byte selector naming the field to show. The field value lives in the device’s on-screen response, not in the code, so nothing personal is encoded here. All 13 selectors mapped by fuzzing an owned device are reconstructed with the project encoder and verified to round-trip; the layout is cross-checked against a real captured serial-query capture.

Payload structure

22-byte container behind a 1-byte length prefix. Only the selector changes between codes; bytes 2–14 are not validated by the scanner (shown here as 11 filler).

Notes

  • Unsigned. C0 codes carry no per-message signature; the token acts on them without validating bytes 2–14.
  • Read-only. These are diagnostic reads — a query code cannot change device state.
  • ✻ unsupported. Selectors 04 (xtal correction) and 06 (use count) return “unsupported” on the tested firmware.
  • KCV vs key. Selector 09 returns the key check value — it verifies a candidate key against the device but does not reveal the key.

Provenance

Selector map and container layout: FORMAT.md §3.1 (ING Digipass scanner, established by fuzzing an owned device). Images generated by cronto/encoder.py at size 25, length framing, and confirmed to decode back to each payload with a valid CRC-24.
